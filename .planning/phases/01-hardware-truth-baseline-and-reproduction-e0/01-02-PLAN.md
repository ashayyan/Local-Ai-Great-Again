# Plan 01-02: Model artifact manifest and compatibility

## Objective
Pin and classify every Qwen3.8-27B artifact needed for complete text-and-image behavior before baseline claims. Do not run inference in this plan; produce a manifest and compatibility report that makes omissions visible.

## Requirements
- REQ-E0-03

## Hypothesis and target
**Hypothesis:** The source model revision, configuration, tokenizer/processor, untied embedding/lm_head, GDN/full-attention blocks, vision tower, and native MTP artifacts can be enumerated and checksummed, with unsupported loader components explicitly classified.

**Numeric targets:** one immutable manifest covering all required component classes; SHA-256 for every present file; architecture fields match the research facts (64 layers, 48 GDN/16 full attention where exposed, hidden 5120, FFN 17408, vocab 248320, untied head, vision and MTP indicators); zero silently omitted components.

## Tasks

### 1. Create manifest script and schema
- Create `scripts/s02_model_manifest.ps1` with explicit model source/revision/path inputs and an offline mode.
- Emit `models/qwen3.8-27b-manifest.json` containing source revision, file names/sizes/SHA-256, config-derived architecture fields, tokenizer/processor revisions, and component status.
- Keep `models/` ignored/uncommitted; commit only scripts and reports/templates.

### 2. Inspect configuration and artifacts
- Enumerate safetensors/GGUF/NVFP4/reference files without loading weights into VRAM.
- Classify language body, untied input/output embeddings, GDN, full attention, vision tower, image processor, tokenizer, and MTP as `present`, `missing`, or `unsupported` with evidence.
- Record model download/cache commands and exact revision; do not treat a partial or text-only checkout as complete.

### 3. Generate compatibility report
- Write `notes/model_compatibility.md` with a component matrix, architecture comparison, loader/runtime version, and explicit fallback routes for any missing support (pinned compatible runtime, WSL2, or fixture).
- Append a pre-registered manifest run to `experiments/LOG.md` with one changed variable and Status / Numbers / Next Experiment.
