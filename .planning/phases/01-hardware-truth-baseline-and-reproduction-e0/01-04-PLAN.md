# Plan 01-04: Frozen quality suite and quantization ladder

## Objective
Freeze reference prompts, calibration/evaluation partitions, multimodal fixtures, and scoring before comparing stock Q4/NVFP4, Q3/IQ3, and Q2/IQ2 variants. Change only quantization between matched runs.

## Requirements
- REQ-E0-05
- REQ-E0-06

## Hypothesis and target
**Hypothesis:** A hashed fixed evaluation harness can compare supported stock quant tiers without mixing model, tokenizer, context, runtime, or prompt changes, and can preserve an FP16/BF16 or NVFP4 reference even when some lower tiers are unavailable.

**Numeric targets:** 50 fixed text prompts, disjoint calibration/evaluation inputs, at least one PPL/comparable text score, and multimodal cases covering OCR, charts, spatial, and multistep reasoning; benchmark each supported Q4/NVFP4, Q3/IQ3, and Q2/IQ2 tier at context 2048 with bytes/load/TTFT/prefill/decode/VRAM/RAM and quality outputs.

## Tasks

### 1. Freeze fixtures and metadata
- Create `scripts/s04_freeze_quality.ps1` and `quality/manifest.json` with prompt/image hashes, tokenizer/processor revision, seeds, context, calibration/eval split, and scoring definitions.
- Store prompts under `quality/prompts/`, images under `quality/images/`, reference outputs under `quality/reference/`; commit small fixtures and manifests, never model weights.
- Ensure no calibration prompt appears in evaluation and all samples have stable IDs.

### 2. Implement scoring harness
- Create `scripts/s05_score_quality.ps1` or a pinned Python helper that scores deterministic text outputs and multimodal categories, records PPL when available, and marks missing/unsupported metrics explicitly.
- Emit machine-readable per-prompt and aggregate JSON plus a Markdown summary.

### 3. Run one-variable quant ladder
- Create `scripts/s06_quant_ladder.ps1` invoking the same baseline settings while changing only quant tier.
- Test Q4/NVFP4, Q3/IQ3, Q2/IQ2; unsupported tiers receive a reproducible availability/failure record instead of omission.
- Capture model bytes, load time, peak VRAM/RAM, TTFT, prefill/decode tok/s, context, quality metrics, and representative outputs.

### 4. Document and log
- Write `experiments/E0_quant_ladder.md` with matched-run table, exact commands, hashes, unsupported evidence, and Status / Numbers / Next Experiment.
- Append all successes and failures to `experiments/LOG.md`; classify measured, derived, externally reported, and hypothesis values.
