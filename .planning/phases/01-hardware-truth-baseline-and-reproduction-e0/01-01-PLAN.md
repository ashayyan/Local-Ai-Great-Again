# Plan 01-01: Hardware truth probe

## Objective
Deliver the measured E0 hardware profile before model work. This is the tracer-first slice: one Windows-native command produces raw JSON, a Markdown profile, and an append-only experiment record; a second invocation demonstrates identity reproducibility and reports measurement variance.

## Requirements
- REQ-E0-01
- REQ-E0-02

## Hypothesis and target
**Hypothesis:** A Windows-native probe can identify the actual laptop SKU and measure GPU/CPU/RAM/PCIe/SSD limits with repeatable medians without assuming the RTX 3050 variant.

**Numeric targets:** two complete runs; identity fields stable across runs; at least 5 timed samples per bandwidth point after warmups; report median and spread; capture GPU copy plus FFN-shaped GEMV/GEMM, CPU RAM bandwidth, pageable/pinned H2D/D2H, SSD sequential/chunked reads, VRAM/RAM availability, and thermal/power context.

## Tasks

### 1. Define pre-registration and schemas
- Create `scripts/s01_hardware_probe.ps1` with a `-RunId`, `-OutputRoot`, `-Warmups`, `-Samples`, and `-SsdTestBytes` interface.
- The script must emit the hypothesis, numeric target, exact command line, UTC timestamp, git commit, host identity, power/AC state, and one-variable-per-measurement metadata before timing.
- Define stable JSON fields for `gpu`, `cpu`, `ram`, `cuda`, `pcie`, `gpu_bandwidth`, `cpu_bandwidth`, `ssd`, `telemetry`, `availability`, and `errors`; preserve raw samples and derived median/spread rather than only headline values.

### 2. Implement Windows-native inventory and telemetry
- Query `nvidia-smi` for GPU name, compute capability/SM, memory total/free, driver, clocks, power, temperature, and PCIe generation/width where available.
- Query PowerShell/CIM for OS, CPU model/core/SIMD indicators, RAM, storage device, Windows power mode, and AC/battery state.
- Missing commands must produce structured `unavailable` records with captured stderr/exit code; independent probes continue.

### 3. Implement bandwidth probes
- Add CUDA/native benchmark invocation or a small pinned benchmark helper under `scripts/` for device copy and representative FFN-shaped GEMV/GEMM (`17408x5120`, `5120x17408`), with warmups and repeated samples.
- Measure pageable and pinned H2D/D2H across declared transfer sizes; use pinned throughput as the T1 planning value and retain link inventory separately.
- Measure CPU RAM bandwidth with a reproducible STREAM-equivalent helper or documented fallback; record SIMD support and method.
- Run a bounded temporary SSD file test for sequential and chunked reads, clean up on success/failure, and never touch `models/` artifacts.

### 4. Generate the profile and ledger entry
- Generate `notes/hardware_profile.json` as raw canonical output and `notes/hardware_profile.md` as the human-readable table replacing all assumed numbers.
- Append a complete entry to `experiments/LOG.md` including command, script/hash, run ID, measurements, failures, and **Status / Numbers / Next Experiment**.

### 5. Rerun and compare
- Run the exact same script twice under the fixed AC/power profile; use a separate run ID only, with no code or settings changes.
- Generate a variance comparison in `notes/hardware_profile.md`; label measured, derived, unavailable, and hypothesis values distinctly.
